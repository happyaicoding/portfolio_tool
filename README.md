# 黃金龜投資組合績效報表

把原本的 Excel(`.xlsm`)計算式改寫成網站與桌面軟體。資料只在本機處理。

## 使用
- 網站:`npm start` 後開 <http://localhost:8000>(或把 `web/` 放到任何靜態主機,例如 GitHub Pages)。
- 桌面版:`npm install` 後 `npm run desktop`;`npm run dist` 打包。桌面版直接載入同一份 `web/`。
- 上傳:CSV / `.xlsx` / `.xlsm`。每檔一個策略(日期、損益),或寬表(第一欄日期,其餘每欄一策略),或原報表的「文字檔」工作表。

## 結構
- `web/src/core.js` 計算核心(MAXDD、MovingDayDD、月/年矩陣、創高天數、資金規劃),無相依。
- `web/src/parse.js` CSV / xlsx 解析,無相依。
- `web/src/config.js` 資料夾設定檔(`portfolio-config.json`)的解析與寫出,純函式、無 DOM,Node 可直測。
- `web/src/app.js`、`charts.js`、`index.html` 介面。`charts.js` 的 `createHeatmap` 畫「逐月盈虧熱力圖」(各策略 × 年份,點年份展開到月;資料來自 `core.js` 的 `strategyMonthly`)。
- `tools/serve.mjs` 網站版本地伺服器(零相依);`tools/check-csv.mjs` 用 CSV 重算並逐格對照參考 `.xlsm`(見下方「更新資料後自己驗數字」)。
- `tests/` 以原 Excel 快取值驗證:`npm test` 依序跑 `parse.test.mjs`(合成 CSV)、`config.test.mjs`(設定檔解析/寫出)、`core.test.mjs`(合成資料的邊界回歸,不需要 Excel)、`xlsm.test.mjs`(完整流程)、`excel-oracle.test.mjs`(逐格對「總表」快取值)。基準檔是專案根目錄那份 `.xlsm`(20 策略版),已 commit,不用另外放置;要換別份就當參數傳路徑。

## 與 Excel 的已知差異
- 日軸尾日:原表把日序列延伸到「更新當天」,多出來的未來日損益為 0,會影響每日浮動區間、95%單日風險值與「近三年」窗口。本工具照同一條規則做(軸尾 = 今天與資料最後日期的較晚者),所以**兩邊要同一天看才對得起來**;`tests/` 是從 `.xlsm` 的 `日週期!G8` 反推軸尾,不會因為改天跑就假紅。
- 開始日期:原表寫在「文字檔 B1」,早於它的資料不納入。上傳 `.xlsm` 時會自動帶入;CSV 沒有這個欄位,請到「設定 → 計算設定」填「起始日」,桌面版會存進資料夾的 `portfolio-config.json`(見下方),重開還在。留空白 = 從資料最早一天算,總獲利/月平均/ROA 就會比原表多算那段。
- 資料結束日期(原表 B30):創高天數以它為截止日,所以也是會被記住的輸入,不是暫時的顯示截斷。填了之後就算 CSV 更新到更晚的日期,報表仍算到那個截止日為止(跟原表一樣)。
- 「最新創高日」與「距離上次創高」:尾端如果已經重新創高,原表公式是 `Y3 = X3 - Z3`,顯示的是最後一段回落段的起點與天數,不是最近一次創高的日期。本工具忠實複刻,不自行改成「最新日」。
- 同一策略同一天出現兩筆以上時,本工具加總;Excel 的 VLOOKUP 只取第一筆。實務上日期應唯一。
- 「保證金檢核」沿用原公式(所需保證金 < 最少資金準備 才顯示 YES),邏輯看起來可能與直覺相反,請自行確認。
- 年度欄:本工具依資料實際涵蓋的年度產生,原表固定 2019–2027,資料沒那長時原表多出來的年欄是 0。

## Windows 免安裝版(portable)
- `.github/workflows/desktop-windows.yml` 在 `windows-latest` 上:跑 `npm test` → `npm run dist:win` 打包 → 啟動打包後的 exe、上傳原 `.xlsm`、檢查畫面數字並截圖。
- 產物在該次 Actions 執行頁的 Artifacts:`PortfolioTool-portable`(單一 `.exe`,雙擊即用)與 `desktop-screenshot`。
- 推 `v*` tag(例如 `v0.1.2`)時,會自動把版號設成 tag 的版號,並把 `PortfolioTool-<版號>-portable.exe` 附到 GitHub Release。
- 尚未簽章,Windows SmartScreen 第一次執行會警告(更多資訊 → 仍要執行)。

## 桌面版:自動讀取資料夾內所有 CSV
- 開啟程式時自動讀取一個資料夾內全部的 `.csv`/`.tsv`/`.txt`(每檔一個策略,或一張寬表);資料夾內檔案有增減或修改,畫面會自動更新,已調整的策略權重與設定會保留。
- 預設資料夾:portable `.exe` 所在的資料夾(開發時可用環境變數 `PORTFOLIO_DATA_DIR` 指定)。可按「選擇資料夾」改成別處,下次啟動會記住。
- CSV 編碼自動判斷(UTF-8,不合法時改用 Big5);分隔符號支援逗號、Tab、分號。策略數量不固定,14 條、20 條都直接吃。
- 第一次使用請到「設定 → 計算設定」填「起始日」,對應原表的 `文字檔 B1`;CSV 檔內沒有這個資訊,留空白會把開始日期之前的資料一起算進去。
- 網站版受瀏覽器限制,無法自動讀資料夾,仍需手動選檔或拖曳。

## 設定檔:`portfolio-config.json`(桌面版)
- 桌面版把「計算設定 + 策略權重」寫成資料夾內的 `portfolio-config.json`(JSON,可用記事本改),所以設定是**跟著資料夾走**:換資料夾 = 換一組設定,把整個資料夾拷到別台電腦也帶著走。網站版沒有檔案權限,仍存瀏覽器 localStorage。
- 內容:
  - `settings.startDate` = 起始日(原表 `文字檔 B1`),`settings.endDate` = 資料結束日期(原表 B30,創高天數以它為截止日),`product`/`ratio`/`calcYear`/`txMargin`/`capital`/`streakThreshold`/`lots` 對應總表的藍色輸入格。日期一律寫 `"YYYY-MM-DD"`。
  - `weights` 是「策略名稱 → 權重」,名稱取自檔名(`1.csv` 就是 `"1"`)。
- 寫檔時機:介面任何欄位一經變更,約 0.4 秒後寫入;內容沒變就不會重複寫。寫不進去(資料夾唯讀、網路碟離線、檔被編輯器鎖住)時畫面會顯示紅字提示,不會假裝存好了。
- 按「重新載入」會重讀設定檔(讓你用記事本改完立即生效);資料夾內 CSV 自動重載**不**重讀設定檔,免得蓋掉還沒落盤的變更。
- 設定檔不影響計算的欄位會被忽略;JSON 壞掉時畫面提示並回到預設值,不會拿半套設定去算。

## 更新資料後自己驗數字:`npm run check-csv -- <資料夾>`
- 只讀該資料夾的 CSV 與 `portfolio-config.json`(執行期真的會用的東西),重算總表後逐格對照專案根目錄那份參考 `.xlsm` 的快取值,印出「相符 N 格 / 不符 M 格」;有任何一格不同就退出非零。
- 沒有 `portfolio-config.json` 或裡面沒有 `startDate` 會直接失敗,不會用預設值偷偷算出一份不一樣的報表。
- 想對別的參考檔:`node tools/check-csv.mjs <資料夾> <xlsm 路徑>`。

## 記錄檔與截圖(桌面版)
- 資料夾內的 CSV 有新增、修改、刪除時,程式會寫一行到資料夾內的 `portfolio-tool.log`(可用記事本開啟,UTF-8),格式:`時間 | 類型 | 內容`,類型有「載入、新增、修改、刪除、截圖」;修改會註明筆數變化(例如 `90 → 91 筆(+1)`)。
- 右上角「📷 截圖並記錄」會把整張總表存成 PNG 到資料夾內的 `snapshots/`,並在記錄檔寫一行當下的關鍵數字(商品與比例、總獲利、最大策略虧、預期年報酬/報酬率、最新創高日)。
- 程式內的「記錄」分頁顯示同樣內容(最新在最上面),下次開啟會接著顯示以前的記錄。
- 記錄檔與 `snapshots/` 是程式自己寫的,不會被當成策略讀進來,也不會觸發重新載入。
- 網站版的記錄只保存在瀏覽器裡(不寫檔案),截圖功能僅桌面版提供。
